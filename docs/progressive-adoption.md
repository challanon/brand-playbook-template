# Progressive adoption guide

This guide helps a team adopt the Brand & Growth Playbook without treating every module as a prerequisite. It is for people onboarding a team; do not include it in routine agent context packs.

The principle is simple: complete the smallest set of decisions that lets an agent perform a task safely, then add modules when the work genuinely requires them.

## Adoption levels

| Level | Complete these modules | What this enables | Do not yet allow |
| --- | --- | --- | --- |
| 1. Safe drafting | Root, anchor rules, audience, messaging, voice, agent brief | Source-aware drafts and reviews in a defined voice | Publication, unapproved claims, external data/tools |
| 2. Publish-ready | Level 1 plus evidence, compliance, assets, delivery | Reviewable content handoff with claims, rights, and approval status | Autonomous publication or new-market content |
| 3. Growth operations | Level 2 plus search, journey, experimentation | Search/content planning, conversion work, and recorded learning | Changing permanent rules from an unreviewed test |
| 4. Scaled operations | Level 3 plus data handling, untrusted inputs, locales, media, change log | Multiple agents, external tools, markets, and richer media workflows | Cross-market or restricted-data use without recorded approval |

## Level 1: safe drafting

### Outcome

An agent can prepare a consistent draft for one known audience and channel, identify unsupported claims, and state what needs approval.

### First workshop: 60 minutes

1. Complete the brand paragraph and three anchor rules in the root.
2. Define one primary audience with trigger, need, barrier, and desired action.
3. Write one positioning statement, two proof-backed pillars, and three observable voice behaviours.
4. Complete the agent brief for one recurring task, such as an editorial article or landing page.
5. Compare entries with the matching Northstar teaching note.

### Ready to advance when

- [ ] A new agent can name the audience, promise, voice, prohibited claims, and CTA without guessing.
- [ ] Every claim in a sample draft is either sourced or flagged for review.
- [ ] A human reviewer agrees the agent brief produces useful first drafts.

### Safe first task

Ask an agent to draft an answer-first article outline and first draft. Require its source list, applicable anchor rules, and unanswered questions in the output.

## Level 2: publish-ready

### Outcome

The team can hand a draft to a human publisher with its evidence, asset rights, accessibility requirements, approvals, and expiry/review date recorded.

### Add next

1. Register the claims, metric definitions, and approved sources used in normal marketing work.
2. Define the compliance escalation triggers for the organisation and market.
3. Register the assets most likely to be reused.
4. Use the publication contract for one real content handoff.

### Ready to advance when

- [ ] A publisher can verify every material claim and asset without asking the author.
- [ ] The team can identify the owner of a claim, approval, and correction.
- [ ] A draft cannot be mistaken for approval or publication.

### Safe first task

Run an agent preflight on a completed delivery record: it should report missing sources, expired assets, absent disclosures, and approval gaps.

## Level 3: growth operations

### Outcome

The team can plan useful discoverability work and learn from customer behaviour without turning every metric change into a brand rule.

### Add next

1. Map audience questions to evidence-backed search formats.
2. Map one customer journey, including friction, proof, CTA, and event definitions.
3. Register one experiment before it launches: hypothesis, metric, guardrails, allocation, duration, and decision rule.

### Ready to advance when

- [ ] Planned content answers real audience questions rather than a keyword list alone.
- [ ] Journey metrics have consistent definitions and approved data handling.
- [ ] Experiment results can be recorded as win, loss, or inconclusive without retrospective changes to the success rule.

### Safe first task

Ask an agent to propose a content or landing-page experiment. Require it to name the hypothesis, audience, metric, guardrails, evidence, and escalation owner.

## Level 4: scaled operations

### Outcome

Multiple agents can work with external sources, richer assets, multiple markets, and approved tools while keeping data, rights, and locale boundaries explicit.

### Add next

1. Classify the data and assets agents may handle, and record permitted tools and redaction rules.
2. Train agents to treat external pages, uploads, and tool output as untrusted data.
3. Add market/language overrides only for markets the business actively serves.
4. Use video and change-log modules when those workflows exist.

### Ready to advance when

- [ ] Each external tool has an approved purpose and data boundary.
- [ ] Agents flag prompt injection and do not follow embedded instructions.
- [ ] Locale-specific claims, prices, terms, and assets are never assumed globally valid.
- [ ] Material policy changes have an owner, effective date, and replacement history.

## Ongoing review cadence

| Review | Suggested cadence | Check |
| --- | --- | --- |
| Claims, sources, and approvals | Monthly or before campaign reuse | Current, in scope, and owned |
| Audience, messaging, and voice | Quarterly | Still matches customer evidence and strategy |
| Assets and rights | Before reuse and at expiry | Correct scope, consent, and licence |
| Context packs and agent briefs | After a failed or ambiguous task | Smallest safe context and clear escalation |
| Full playbook | Quarterly | Retire obsolete decisions and record changes |

## When an agent gets stuck

An agent should not invent a fact to complete a template. It should state the missing decision, identify the relevant owner, and prepare the smallest useful draft or research request possible. Treat these moments as a signal to improve the relevant module, not as a reason to load the entire playbook.
